# 说明书骨架模板

> 成稿的唯一模板。七章固定骨架，顺序不可换；按目标类型微调（见文末表）。
> 篇幅：正文约 1500–3000 字（代码块不计）是**参考区间，不是硬性指标**——素材支撑多少就写多少，内容说清为止；🚫 禁止为凑字数注水，也不为压字数砍有效信息。可扫读优先——短段落、多表格、示例先行。

```markdown
# <目标名> 使用说明书

> 一句话定位。版本基准：素材对应版本 vX.Y.Z（抓取于 YYYY-MM-DD）。

## 目录

- [[#1. 简介与定位]]
- [[#2. 安装与配置]]
- [[#3. 快速上手]]
- [[#4. 核心功能]]
- [[#5. 常见问题与坑]]
- [[#6. 进阶技巧]]
- [[#7. 资源链接]]

## 1. 简介与定位
- 是什么、解决什么问题、适合谁
- 与同类工具的关键区别（1–2 句，须有官方来源）
- 3–5 句说完，禁止堆砌 feature 清单

## 2. 安装与配置
- 多平台安装命令（表格：平台 | 命令）
- 最小配置（如无配置项，写「零配置」并给验证命令）
- 验证安装成功的命令 + 预期输出一句话

## 3. 快速上手
- 3 个递进示例：最小可用 → 常用场景 → 组合用法
- 每个示例：命令/代码块 + 一句话说明预期效果

## 4. 核心功能
- 按功能域分组（CLI 按子命令/flag 分组；库按 API 域分组）
- 每组：用途一句 + 来自素材的命令/代码示例
- 末尾一张「常用命令/API 速查表」

## 5. 常见问题与坑
- 素材来源：近 30 天社区讨论 + GitHub 经典 issues（不限时）
- 每条三段式：现象 → 原因 → 解法
- 每条附来源链接 + 抓取日期

## 6. 进阶技巧
- 组合用法、性能调优、脚本化、鲜为人知的功能
- 只写素材中出现的技巧；禁止「据说」「可能可以」

## 7. 资源链接
- 官网 / 官方文档 / GitHub / 社区入口
- 汇总本文引用的全部来源（链接 + 抓取日期）
```

## 按类型微调

| 目标类型 | 章节微调 |
|---|---|
| CLI | §2 重多平台包管理器（brew/winget/npm/pip/cargo 等并列）；§4 按子命令分组 + flag 速查表；§6 重管道组合、别名、shell 集成、脚本化 |
| 开源库 | §2 按语言包管理器给安装命令；§3 为最小可运行代码示例（可整段复制执行）；§4 按 API 域分组；§6 重配置项、性能、插件/生态 |
| 框架 | §3 含项目初始化命令；§4 先讲核心概念（路由/状态/生命周期等，不超过 3 个）再列功能；§6 重工程化实践（目录组织、构建、部署） |
| MCP server | §2 重客户端配置：给出 Claude Code / Cursor 等主流客户端的配置 JSON 完整代码块；§3 为「验证连接 + 首次调用」；§4 列暴露的 tools/resources 清单（表格：名称 | 作用 | 关键参数） |

## 写作硬规则

1. 正文一律中文；命令、代码、flag、API 名、专有名词保留原文。
2. 每个命令/配置/flag 必须能在 research/ 素材中找到出处；素材没有的功能不写。
3. 关键论断（性能数据、兼容性、限制）后附来源：`（来源：[标题](URL)，抓取于 YYYY-MM-DD）`。
4. 事实层与补充层冲突时以事实层为准，并在该段标注「社区有异议：<一句话>（来源：…）」。
5. 示例中的占位符用尖括号（如 `<你的token>`），不使用真实密钥样式的字符串。
6. 头部目录为 Obsidian 风格 `[[#...]]` 链接：只列七章 H2（不收 H3 子节），链接文字必须与章节标题逐字一致——Obsidian 锚点按标题全文精确匹配，差一个字即失效。
